# Knowl v0.8.0

This release moves dense vector ranking into SQLite and PostgreSQL, preserves
historical audit diagnostics, and replaces the bundled project wiki with a
fresh Gemini 4 Argon generation.

## Native vector retrieval

- Run exhaustive cosine ranking inside bundled, CGO-free SQLite `sqlite-vec`
  or optional PostgreSQL `pgvector`, rather than transferring every stored
  vector into Go. Aggregate chunk and query-window scores to page winners
  before applying the candidate limit; keep source filters and deterministic
  tie-breaking.
- Validate complete vector state at publication, reuse, and recovery. Queries
  check bounded scalar readiness, snapshot, model, dimensions, and format
  identity while retaining validation of the returned original evidence.
- Keep existing projection and request limits, lexical fallback policy, and
  external embedding-provider configuration. No ANN index or in-process
  embedding model is introduced.
- Record reproducible measurements without claiming a universal speedup:
  PostgreSQL remains slower than the Go baseline for some filtered cases.
  See the [native vector report](../testing/native-vectors.md).

## Wiki and diagnostics

- Replace the bundled wiki with eight subject-oriented pages generated from
  scratch using Antigravity `gemini-4-argon-medium`, with citations covering
  all 26 documentation sources used for that generation.
- Preserve existing immutable raw revisions and append-only audit history.
- Identify logged commits by operation ID and plan generation together. Treat
  identical repeated records as warnings, conflicting records as errors, and
  logged file paths as historical targets that may since have been deleted.
- Keep self-wiki validation independent of model-generated page names while
  retaining representative resolved-source coverage.

## Installation

After publication, run from a local project root:

```bash
npx --yes @baldaworks/knowl@0.8.0 setup codex
```

Native npm packages cover macOS x64/arm64, Linux x64/arm64, and Windows x64.
The container remains available for Linux amd64 and arm64.

## Upgrade and recovery

Stop workspace writers and back up the canonical workspace and operational
database before upgrading. Existing Markdown and immutable source revisions
remain authoritative; SQL/search vectors are rebuildable projections.

Base SQL Goose migration 26 invalidates legacy dense state. SQLite includes its
native vector capability in the binary. PostgreSQL lexical-only operation does
not require `pgvector`; before enabling PostgreSQL embeddings, provision the
extension as an operator and use the separately versioned optional SQL Goose
migration track. Knowl does not run `CREATE EXTENSION` automatically. See the
[PostgreSQL migration guidance](../postgres.md) before upgrading an embedding-enabled
installation, and rebuild projections with the new binary before relying on
hybrid retrieval. Do not run old and new workspace writers concurrently or
blindly downgrade across the new projection format.

See [publishing](../publishing.md) for release verification and distribution
details, and the [v0.7.0 upgrade guidance](v0.7.0.md#upgrade-and-recovery)
when upgrading from an older release.
