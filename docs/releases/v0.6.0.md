# Knowl v0.6.0

This release adds the repository-supplied local Codex plugin and stages the
Knowl CLI for npm as `@baldaworks/knowl@0.6.0`.

From a local project root, the supported bootstrap is:

```bash
npx --yes @baldaworks/knowl@0.6.0 setup codex
```

The plugin contains only the `setup` and `run` skills and registers the same
three Knowl tools through host-owned MCP stdio. It needs no local HTTP daemon,
port, operator token, or separate `codex mcp add`. Existing explicit HTTP
sidecar and embedded-Go deployments remain supported.

The run skill accepts a local CLI only when its structured version identity is
exactly `0.6.0`; otherwise it keeps the complete run on the pinned
`@baldaworks/knowl@0.6.0` npm launcher. Project maintenance still requires the
configured maintainer provider.

Staged native packages cover macOS x64/arm64, Linux x64/arm64, and Windows x64.
Setup can fetch both npm artifacts and a pinned, sparse Git marketplace. Sparse
checkout limits materialized paths; it is not a metadata-only fetch guarantee.
Offline use should be prewarmed while those exact artifacts are reachable.

The verified scope is local Codex with project state on a local filesystem.
Hosted or remote plugin execution, remote MCP hosting, and shared/network
filesystems are not supported by this release. Concurrent local processes for
one project coordinate the durable store and workspace; separate project
working directories remain isolated.

The npm artifacts and plugin are implemented and verified in the repository;
this note does not claim that the package has been published. Publication
requires the separately authorized release workflow, a v0.6.0 tag on `main`,
green repository/integration/container/npm checks, and npm credentials. This
implementation does not publish npm packages, create a tag or GitHub release,
push a branch, or open a pull request.
